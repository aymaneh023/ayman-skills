# Ticket brief

The brief is the comment `triage` posts on a `ready-for-agent` ticket. Write it as Matt's `triage` AGENT-BRIEF says, and add the parts below. The agent that builds the ticket runs alone in a worktree. If it would have to ask something, the brief is not done.

## Extra parts

**Test seams.** Where the agent tests from the outside, agreed with the user now (the agent's `tdd` step needs agreed seams and cannot ask). One line each: what the seam catches. A seam names what the test feeds in, and follows the repo's `CODING_STANDARDS.md`. For work around a language model, the seam is the step after the model (a draft as plain input), never the conversation with it.

> - `classify_products(company)` returns groups for a retailer. Catches wrong grouping.

**Scenarios.** The scenarios from the spec that this ticket covers (its `Covers:` line), copied word for word with their IDs. They are the goal: the work is done when each one holds. Write the tests for them at the seams below, with the scenario ID in the test name (`test_as_2_products_grouped_by_category`), so the PR can show which test proves which scenario.

**Done check.** A command or check the agent can run itself, that passes only when the work is done: the tests for the covered scenarios pass. No paid calls, no deploys.

> - `uv run pytest tests/test_products.py` passes.
> - `uv run ruff check src/products` is clean.

If the real proof needs a paid run (an eval, a Perplexity call), write that under **For the user** instead. The agent prepares it and does not run it.

**Level.** `light`, `standard` (default) or `heavy`. See [tools.md](tools.md).

- `light`: docs, small config changes, summaries, `/durable-docs`.
- `standard`: normal code, prompts, queries.
- `heavy`: new agent logic, a hard prompt redesign, a change across many parts.

**Tool.** Leave empty, unless there is a reason to name one (`claude`, `codex`, `copilot`). Example reason: "try this one in Codex".

**For the user.** Steps only the user does after the agent finishes: paid runs, deploys, a manual check. The agent lists them with exact commands.

## Example

```
> *This was generated by AI during triage.*

## Goal
...as triage writes it...

## Scenarios
Covers: AS-2
  Scenario: AS-2 A retailer's products are grouped by category
    Given a retailer with products in three categories
    When its products are classified
    Then each product is in the group of its category

## Test seams
- `classify_products(company)` returns groups for a retailer.

## Done check
- `uv run pytest tests/test_products.py` passes.

## For the user
- Paid check: `uv run python scripts/try_agent.py --topic products`

Level: standard
Tool: (empty)
```
